# 电脑配件进销存管理系统后端接口需求文档

## 1. 项目技术结构

本项目采用前后端分离方式开发：

```text
React 前端
  ↓ HTTP 接口 / JSON 数据
Python 后端
  ↓ SQL
MySQL 数据库
```

前端不直接连接 MySQL，所有数据都通过 Python 后端接口获取。

## 2. 接口统一约定

### 2.1 基础地址

开发阶段建议：

```text
http://localhost:5000/api
```

如果后端运行在后端同学电脑上，前端需要访问后端同学电脑的局域网 IP，例如：

```text
http://192.168.1.23:5000/api
```

### 2.2 返回格式

建议所有接口统一返回：

```json
{
  "code": 200,
  "message": "success",
  "data": {}
}
```

列表接口返回：

```json
{
  "code": 200,
  "message": "success",
  "data": []
}
```

错误返回：

```json
{
  "code": 400,
  "message": "该 SN 码已售出，不能重复销售",
  "data": null
}
```

### 2.3 跨域要求

React 前端开发服务通常运行在：

```text
http://localhost:5173
```

Python 后端需要开启 CORS，允许 React 前端访问接口。

如果使用 Flask，可以参考：

```python
from flask_cors import CORS

CORS(app)
```

## 7. 联调注意事项

### 7.1 字段命名

建议后端返回给前端时使用驼峰命名：

```text
product_id      → productId
product_name    → productName
category_name   → categoryName
brand_name      → brandName
warning_value   → warningValue
created_at      → createdAt
```

这样 React 前端使用更方便。

### 7.2 金额字段

金额字段建议统一返回数字，不要直接返回带 `¥` 的字符串。

正确：

```json
{
  "salePrice": 1899
}
```

不建议：

```json
{
  "salePrice": "¥1899"
}
```

### 7.3 日期字段

日期字段建议统一格式：

```text
YYYY-MM-DD
YYYY-MM-DD HH:mm:ss
```

### 7.4 事务处理

以下接口必须使用事务：

```text
POST /api/purchase-orders
POST /api/sales-orders
POST /api/purchase-returns
POST /api/sales-returns
POST /api/transfers
POST /api/stocktakes
```

尤其是采购入库和销售出库，会同时修改多张表，必须保证数据一致性。

### 7.5 SN 码规则

建议后端生成 SN 码，前端不负责生成。

示例：

```text
CPU-INTEL-20260607-0001
SSD-SAMSUNG-20260607-0001
MB-ASUS-20260607-0001
MEM-KINGBANK-20260607-0001
```

## 9. 配件停用与恢复接口补充

配件管理不建议做物理删除。为了保证历史采购、销售、库存和 SN 追踪记录完整，前端的“停用”按钮应对应后端状态更新接口。

### 9.1 停用配件

```http
PUT /api/products/:id/status
```

请求示例：

```json
{
  "status": "停用"
}
```

返回示例：

```json
{
  "code": 200,
  "message": "配件状态已更新",
  "data": {
    "id": 1,
    "status": "停用"
  }
}
```

业务说明：

```text
1. 停用后不删除 product 记录。
2. 停用后历史采购、销售、库存、SN 记录仍然保留。
3. 停用后的配件不允许出现在新建采购单、新建销售单的可选列表中。
4. 配件管理页面仍然可以查看停用配件。
```

### 9.2 恢复配件

```http
PUT /api/products/:id/status
```

请求示例：

```json
{
  "status": "在售"
}
```

业务说明：

```text
1. 恢复后该配件可以重新用于采购、销售和库存管理。
2. 恢复不代表库存充足，库存是否预警仍由 stock.quantity 和 product.warning_value 判断。
```
