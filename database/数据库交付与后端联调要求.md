# 数据库交付与后端联调要求

## 1. 目的

本项目当前分工：

```text
数据库同学：负责 MySQL 数据库设计、建表、视图、存储过程、触发器、测试数据
我方：负责 Python Flask 后端 + React 前端
```

为了保证后端能顺利连接数据库、编写接口，并让前端页面能正常显示数据，数据库部分需要提供清晰、稳定、可执行的交付内容。

后端最怕的问题不是“数据库没有表”，而是：

```text
字段名不确定
字段类型不统一
状态值不统一
测试数据覆盖不到前端页面
视图字段缺失
外键关系不清楚
SQL 脚本不能从空库完整执行
```

所以本文档主要用于约定：**数据库需要交付什么、字段应该怎么命名、后端会依赖哪些表和视图。**

## 2. 项目技术结构

```text
React 前端
  ↓ Axios 请求 JSON
Python Flask 后端
  ↓ PyMySQL / SQLAlchemy 执行 SQL
MySQL 数据库
```

前端不会直接连接 MySQL。  
后端 Flask 会根据数据库字段编写接口，再把数据转换成 JSON 返回给前端。

## 3. 数据库基础信息

建议：

```text
数据库类型：MySQL
数据库版本：MySQL 8.x
数据库名称：computer_parts_inventory
字符集：utf8mb4
排序规则：utf8mb4_unicode_ci
存储引擎：InnoDB
```

如果实际数据库名称不同，请数据库同学明确说明。

## 6. 字段与类型建议

字段名建议使用英文小写 + 下划线。  
后端返回给前端时会再转换成驼峰命名。

例如：

```text
product_id      → productId
product_name    → productName
sale_price      → salePrice
warning_value   → warningValue
```

## 7. 必须统一的状态值

## 7.1 product.status

只建议使用：



```text

```


## 9. 测试数据要求

测试数据数量由数据库同学根据实际情况自行决定，不强制规定每张表必须多少条。

但必须覆盖以下前后端联调场景：

```text
1. 品牌下拉框有数据。
2. 分类下拉框至少包含 CPU、内存条、硬盘、主板。
3. 配件列表能查到不同分类的商品。
4. 每种分类至少有一条对应属性表数据。
5. 仓库下拉框有数据。
6. 供应商下拉框有数据。
7. 客户下拉框有数据。
8. 库存汇总页面能查到库存。
9. 至少有一条低库存数据，用于测试库存预警。
10. product_sn 中至少有“在库”的 SN，用于销售单选择。
11. product_sn 中最好也有“已售”或“锁定”的 SN，用于测试状态校验。
12. 销售统计视图能查出图表数据。
```

换句话说，数据多少可以自行判断，但不能出现：

```text
前端下拉框为空
库存页面为空
SN 查询查不到任何数据
报表页面没有数据
```

## 10. 逻辑删除 / 停用规则

配件不建议物理删除。

原因：

```text
product 可能已经被采购明细、销售明细、库存和 SN 记录引用。
如果真实删除 product，会破坏历史业务数据。
```

建议：

```sql
UPDATE product SET status = '停用' WHERE product_id = ?;
```

恢复：

```sql
UPDATE product SET status = '在售' WHERE product_id = ?;
```

后端接口会按以下方式设计：

```http
PUT /api/products/:id/status
```
